# 家計・返済プランナー v6.0 RC

[アプリを開く](https://nagoyan-bit.github.io/finance-planner/)

家計簿、借金返済、資金繰り、口座管理を一体化したPWA。v6.0 RCは正式安定版候補です。計算テストは実施済みですが、最新版の実機・ブラウザ・クラウド同期の確認が残っています。

## 最初に設定すること

1. 設定画面からJSONバックアップを保存（既存利用者は更新前に実施）。
2. 口座画面で口座ごとの実残高・用途を登録。緊急貯金口座は通常口座と区別する。
3. 借金画面で元金、最低返済額、年利、返済日、利息起算日、返済元口座を入力。
4. 家計簿のカード設定で締め日・引落日・引落口座・確定請求額を入力。
5. 設定で月予算、生活費、自由費、緊急貯金目標、今後の月別収入・返済予定を入力。
6. 収入配分画面で給与の入金日・予定額を登録。実際の入金があったら確定する。

## 日常の使い方

| 場面 | 操作 |
| --- | --- |
| 朝 | ホームで今日の使用目安、支払い予定、資金不足予測を確認 |
| 買い物 | 家計簿で利用日、金額、支払い方法を記録 |
| 給料日 | 収入配分で実際の入金を登録、資金配分を確認 |
| 口座振替 | 銀行で実際に移動してから口座画面で振替を記録 |
| カード引落 | カード請求画面で引き落とし実績を登録 |
| 借金返済 | 実際の支払総額・うち利息を入力して返済実績登録 |
| 月末 | 振り返り、残高照合、翌月の準備、JSON保存 |

カード利用時には家計簿の支出を記録し、引落時には現金残高のみを減らす。通常口座間の振替は総手元資金を変えない。緊急貯金への移動は手元資金から緊急貯金への振替となる。承認した配分は予定であり、銀行への自動送金は行わない。同じ返済を配分予定と借金画面の両方から実績登録しない。

## 予測の読み方

- 7/30/90日の資金予測は登録済み入金・支払予定に基づく。同日中は引落が先と仮定。
- 日付未設定の月別収入は日別予測には含めない。月別予測とは結果が異なることがある。
- 月末支出見込みは平均支出ペースによる概算。固定費は登録予定と手動予算の大きい方を用いる。
- 返済額や利息は実際の明細を優先。予測完済時期は将来の収入・支出・金利で変動する。
- カード引落の休日補正は土日のみ。祝日や銀行ごとの扱いは自分で確認する。
- 返済ダッシュボードの初期比残高減少と記録済み元金返済は別指標。カード未払いは借金総額に含まない。

## 保存・同期・プライバシー

初期状態は空。公開GitHubに個人の家計データは含めない。通常はブラウザ内に保存する。任意のクラウド同期を設定すると、専用Supabaseの認証ユーザーのデータとして保存する。同期は競合時に自動上書きせず、利用者が選択する。秘密キーは入力しない。ログイン保持を選択した端末ではセッショントークンがローカルストレージに保存される。共有端末では保持を避ける。PINロックは暗号化ではない。JSONは個人情報を含むため公開リポジトリにアップロードしない。

同期に問題がある場合は両端末でバックアップし、最終同期時刻と内容を確認してから同期する。競合画面でどちらを採用するか決めるまでデータを上書きしない。

## スマホへの追加

ブラウザでアプリを開き、ブラウザのメニューからホーム画面に追加。更新が反映されない場合はオンラインで再読み込みし、アプリを閉じて開く。保存データを消去する操作はバックアップなしで行わない。
